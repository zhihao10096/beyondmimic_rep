# 实验协议与验收

本文件的数值阈值是**工程验收建议E**，不是论文原始协议或承诺达到的数字。版本v1，2026-10-01。任何阈值调整需在首次正式test前冻结，写明理由，不得测试后改门槛。

## 1. 四个闭环关口加环境关口

| 关口 | 验证对象 | 必须具备的证据 | 建议最低门槛 |
|---|---|---|---|
| G0 | 环境/robot | headless1/32env实际物理step、reset、CUDA、joint/body映射 | 可重复启动并关闭；100ticks无异常/NaN；频率匹配 |
| G1 | 25Hz teachers | 从phase0完整motion播放，随机phase、独立seed与扰动 | 入库motion完整回放20次成功率≥95%；物理失败与motion结束分开 |
| G2 | 统一VAE | student-only、多motion，clean与扰动，DAgger迭代曲线 | 每入库motion clean成功率≥90%；较teacher下降≤10百分点；body误差不大于teacher1.25倍 |
| G3 | 无引导diffusion | reference-free环境、物理执行、多seed/扰动、无teacher辅助 | upright locomotion15s、50trials成功≥90%；无反泄漏失败；预测/实际误差与动作分布无明显异常 |
| G4a | low-dynamic任务 | 同一checkpoint上的velocity、waypoint、全身avoidance、inpainting | velocity/waypoint成功≥80%；相对unguided错误下降≥30%；avoidance碰撞≤10%且仍到达 |
| G4b | 完整能力覆盖 | 多风格走跑、切换、动态技能和接触技能inpainting、任务composition | 每种预注册能力≥20trials，报告成功率；初期目标≥80%，无teacher接管；失败项明确未完成 |

G4b动态能力的80%是研究目标而非可自动降低范围的条件；如果训练数据或模型尚达不到，应继续实验并记录限制。满足G4a可以交付一个阶段性全链路模型，不能宣称论文全部技能复现。

G1/G2阈值可以因运动类型重新预注册，如长参考一次失败就算失败会更严格；保持teacher和student同协议。低速最小库至少两种walk和一种run；第一walk链路仅是调试里程碑。

## 2. “成功”和“终止”分开定义

teacher/VAE tracking评估：参考phase0连续完整播放，无internal reference resampling、无环境随机reset、无teacher接管。记录完成时间和各种终止。参考结束是success；训练episode timeout不是完整motion成功。

upright locomotion评估：物理fall按head高度<0.2m、持续不稳定姿态等预注册判断；head需从真实模型解析，不在14body state中找一个近似。termination提前发生计为失败，不只看step完成率。

**高动态和接触动作不能套用固定pelvis/head高度门槛。** 起身、躺下、翻滚、cartwheel会合法降低身体高度；使用任务关键帧序列、最终恢复站立/locomotion和实际接触约束。记录致命碰撞/NaN/失控而非参考误差终止。不要把R1默认root_height0.40m等直立保护当所有技能通用终止。

waypoint成功：20s内距离≤0.25m且planar速度≤0.15m/s维持0.5s（E）。只到达又冲过去不算stop成功。超时、fall、collision分别列出。

inpainting成功：关键帧位置/姿态误差在预先定义范围（起点建议主要body位置RMSE≤0.15m，姿态≤20°），全过程保持任务对应的可接受接触，之后回到指定模式至少3s。时间对齐容许范围预先冻结，不能逐trial人为挑最佳帧。

avoidance成功：达到目标且全程没有指定非地面障碍碰撞；每身体球的实际clearance单独报告。地面足接触不算障碍碰撞，sensor与碰撞对象识别必须明确。

## 3. 数据与基础数学必须通过的测试

下表是有实际风险的测试，不要求对每个配置getter或简单封装写镜像测试。

| Test ID | 验证内容 | 判据 |
|---|---|---|
| C01 | joint/body名称、CSV→native映射 | 29/14一致，唯一，不靠数组长度猜顺序 |
| C02 | quaternion和Rot6D含义 | wxyz/xyzw、identity、90°轴转、q与-q；R→6D→R误差≤1e-5 |
| C03 | 官方teacher adapter等价 | 同input deterministic action max差≤1e-5；normalizer只调用一次 |
| C04 | action→PD target | 同运行时default/scale，a0对应default；不双乘scale；与env processed action一致 |
| C05 | one-step时序 | 行t实际state、当前z/a、next实际state明确；a_last来自已执行上步动作 |
| C06 | DAgger真实性 | 对标识mock/小真实env，执行student action，teacher标签在student状态取值；不并行跑独立teacher状态 |
| C07 | reset/motion wrap边界 | 部分env reset不会污染其他env；内部phase跳变也切episode；window不跨边界 |
| C08 | root frame变换 | global平移/yaw后hybrid特征不变；root current p/v为0；actual velocity恢复误差≤1e-5 |
| C09 | projection与inverse | P_pinv P回环≤1e-5；checkpoint恢复得到相同P/hash；normalization顺序一致 |
| C10 | mirroring | M²=id、FK左右匹配、polar/axial vector符号正确；mirrored z经decoder与mirror(action)匹配 |
| C11 | OU | 复现seed、reset独立、平均/方差合理；dt1.0与control dt分开；accepted prefix失败后整段拒绝 |
| C12 | mask semantics | 历史s/z与当前s始终固定；当前z可改变；future keyframe只影响指定维度 |
| C13 | noise schedule与reverse | clean0无noise，末级signal≈0；perfect x0 oracle reverse能恢复干净数据；x0/epsilon转换一致 |
| C14 | EMA/gradient accumulation/DDP | optimizer step计数正确，warmup按update计；accum单次大batch等价；resume保持scheduler/EMA/RNG |
| C15 | guidance autograd | finite-difference相对误差建议≤1e-3；在约束之外small step降低cost；SDF barrier在delta连续且一阶导一致 |
| C16 | policy引用信息泄漏 | 固定actual/RNG，reference/phase/motion_id打乱不影响stage3 action；teacher calls0；encoder可移除 |
| C17 | actual history | rollout日志中的历史与真实传感数据一致；不能用预测state覆盖actual；每tick重锚定 |
| C18 | end-to-end latency | CUDA synchronize后计时、batch1/真实20step+guidance；异步plan age与执行tick匹配 |

镜像latent检查若无法通过，关闭该扩散augmentation并继续用真实镜像rollout采集；不是复制z后放宽测试。坐标/频率/数据泄漏任一失败都应阻断长训练。

## 4. 数据审计指标

每个teacher/motion/DAgger round/OU shard至少输出：sample count、合法episode数、时长、accepted率、每类reject reason、reference phase覆盖、清零比例、NaN/Inf、shape/dtype、观测和action分位数、joint/速度范围、quat norm、a_last一致性。

split以collector run/完整episode为单位；每个镜像数据与原数据同split。报告window source intersection应为0。原motion没在VAE/diffusion训练中的跨motion测试另列，不能与seen-motion heldout rollout混成一个“泛化成功率”。

OU采集的拒绝比例必须显示：如果filtered训练集很漂亮，但困难motion90%episode被拒绝，不能称广泛覆盖。困难phase无accepted数据应反馈至teacher/VAE。

latent audit：mu均值/方差、posterior sigma、每维KL、有效latent维度、latent分位数、z打乱对action/闭环的影响、跨motion可分性。decoder仅靠proprio即可predict action时可能存在posterior collapse，必须定位。

## 5. 物理任务协议

默认每个最终condition50trials；当前每motion teacher只训练1个固定seed，但用独立评估seed/初始phase/扰动进行多次rollout。阶段2/3主线也先完成1个模型，不以多训练seed为前置。最终训练方差研究可选3个模型训练seed，报告中明确实际数量；评估seed与训练/validation分离。所有成功率报告分母、Wilson95%interval，禁止只报最好seed或只保存成功视频。

### A. Tracking与VAE

clean：完整motion和random starts；matched扰动：相同friction/COM/offset与push样本。teacher与student相同seed和reset相位。

指标：完整completion rate、fall rate、完成时长、body位置RMSE（world与yaw/anchor-relative分别报）、anchor位置/姿态误差、body linear/angular velocity误差、joint误差（诊断）、action rate、torque saturation、自碰撞。

聚合同时报macro每motion平均和sample-weighted总平均，避免长walk淹没短cartwheel。

### B. 无引导diffusion

立姿locomotion15s，无command：不会追指定参考，应评价稳定执行分布、实际速度范围和motion style。相同初始化test比较不加push/加push，push间隔1s、速度变化大小0–0.5m/s是借鉴早期协议的E测试，不称v4原实验。

指标：fall率、survival curves、actual root速度/高度/roll/pitch、动作与torque分布、prediction horizon逐步误差、actual–predicted一致性。预测误差在另一z采样轨迹上比较没有意义，必须对实际执行对应plan评估。

### C. 速度与转向

在训练motion实际速度支持范围内预注册commands，先±0.2/0.4m/s横/纵向及±0.2/0.4rad/s yaw；run目标由实际dataset velocity percentiles定，不凭空设超分布高速。采用forward→backward→left→right各3s序列，加turn和stop；另有随机piecewise命令20–30s。

report plan预测RMSE、actual RMSE、settling时间、heading/yaw rate误差、command follow success、fall。用物理m/s绝对误差主报；零目标附近百分比误差没有意义，若报relative需定义denominator与epsilon。v4报告的12.14%/13.65%没有完整公开本地协议，不能直接把任意百分比指标与其比较。

### D. 航点、障碍与任务组合

无障碍waypoints：不同方向1–3m，goal frame明确世界坐标，停止验收。静态障碍：圆柱/box在直线路径上，以手/肘/torso等球clearance和实际contact判定，位置/尺寸分validation/test；窄通道等初期作为困难扩展。

比较unguided、waypoint-only、waypoint+SDF、velocity+SDF。不能用“不动”实现零碰撞，必须同时达到目标/保持有效速度。避障地图只用于cost，动作网络本身不额外训练场景任务。

### E. Inpainting与模式切换

progression：walk keyframes→walk/run切换→数据支持的dynamic skill→lie/get-up→返回walk。keyframes每0.2s稀疏目标，当前latent不锁定；记录关键帧误差、任务完成、切换时间、fall、动作突变和contact。

同一模型执行velocity→inpainting→velocity，以及waypoint+avoidance与keyframe模式切换。不把teacher参考追踪作为inpainting成功。

## 6. 消融优先级

| 优先级 | 对照 | 作用 |
|---|---|---|
| 必须 | BC-only vs BC+DAgger | student-state分布纠偏是否有效 |
| 必须 | teacher vs VAE vs diffusion同场景 | 确定质量损失来自哪阶段 |
| 必须 | unguided vs guided同checkpoint/初始化 | 任务控制增益 |
| 必须 | clean数据 vs OU error-band数据 | 抗扰动能力和OOD恢复 |
| 必须 | latent正常配对 vs shuffled，z固定0 | 检查潜变量确实承担控制信息 |
| 高 | KL sum/mean及有效beta | 数值定义是否影响posterior collapse |
| 高 | 25Hz主线 vs 独立50Hz支线 | 时间尺度的重要性；不能共用不匹配权重 |
| 高 | full-state/body-pos vs joint-only | 体现state表示的必要性，作为独立模型 |
| 高 | c6投影 vs 无projection vs R1 root-only projection | 未公开projection细节的实现影响 |
| 高 | DDPM vs DDIM20步 | sampler偏差与性能 |
| 高 | history4 vs0/2；末端noise与mask策略 | 稳定性/任务切换权衡 |
| 扩展 | mirror合法重encode vs no mirror | 技能覆盖与语义相容性 |
| 部署 | 同步 vs异步；0/1/2tick延迟 | 现实推理延迟影响 |

先做基础关口；每次失败不同时搜索几十参数。v1无VAE/4heads等配置不作为“优化”悄悄覆盖v4主线。

## 7. 失败现象→定位顺序

| 现象 | 先检查 | 然后实验 |
|---|---|---|
| teacher即刻倒下 | joint映射、normalizer、checkpoint task、qtarget/default、freq/NPZ | 原play与adapter逐项比较 |
| VAE loss低但闭环差 | s/a错位、a_last、q绝对/相对、input normalizer、latent执行/保存不一致 | BC→DAgger、KL/z sensitivity |
| VAE只会平均动作 | KL reduction/scale、decoder忽略z、数据motion失衡 | zero/shuffled-z、逐motion训练对照 |
| diffusion看似生成正常但机器人倒下 | latent反归一化、decoder最新proprio、clean0/mask、reference泄漏 | perfect latent replay经过decoder；teacher/VAE轨迹比较 |
| predicted velocity满足目标，实际不动 | v_rel恢复忘加v_t、state–z配对、state-only guidance | latent/action对guidance变化，actual计划误差 |
| cost下降但动作剧烈/摔倒 | gradient过大、错单位、P逆/归一化、不合理command | weight0基线；分noise-step grad norm |
| reset后第一步坏，其他时候稳 | padding、a_last、partial reset、旧plan/old-frame history | 单env重复reset/部分envreset |
| 避障过但手撞障碍 | root-only成本、body世界恢复、球半径、真实contact过滤 | 全身clearance逐body可视化 |
| inpainting破坏当前平衡 | 当前z被锁、未来所有token被锁、keyframe坐标/时间错误 | 仅单关键帧/少维度约束，再扩展 |
| 训练1000epochs极慢 | 全windows复制、worker重复巨大数组、batch/epoch误定义 | lazy dataset、逐update吞吐核算 |
| PyTorch通过但MuJoCo失败 | robot asset、gain/armature、torque/速度限制、rootlink/COM、观测顺序 | teacher→VAE→diffusion分层对齐 |

## 8. 结果文件最小结构

每实验独立run目录：`config_resolved.yaml`、`environment.json`、`sources.json`、`metrics.json/csv`、`per_episode.csv`、`model_manifest.json`、`videos/`、`failures/`、`latency.csv`。metrics里有seed、condition、motion/task、success、failure_reason、duration、error、latency、models/data/contracts hashes。

各关口生成Markdown报告；必须附代表性成功和失败视频、包含摔倒的未剪辑episode，给后续诊断足够实际记录。数据/权重可在大文件存储，仓库只提交small manifest、commands和可读报告。
