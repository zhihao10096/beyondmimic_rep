## 4. 本地可执行规模建议

这些是profile起点，不是硬件能力承诺。

| 工作 | 起点 | 后续扩大条件 |
|---|---|---|
| 启动与状态核验 | 1 env，然后32 env | G0通过 |
| teacher短训 | 128或256 env，20–100iterations | 记录VRAM峰值/吞吐；再512/1024 |

## 5. 12×4090的工作安排

12张卡显存相互独立；不能把总288GB当单卡内存。每个独立collector/teacher进程绑定一个 `CUDA_VISIBLE_DEVICES`，其内部统一使用`cuda:0`，避免设备索引错位。这只选择设备，不要求特定CUDA版本。

| 阶段 | 推荐调度 |
|---|---|
| teacher | 首轮4台服务器各训练1个不同动作，使用各自GPU0，seed/num_envs沿用仓库默认；余卡验证/扩库 |
| D0/DAgger | GPU0–11按motion分别采集相同student hash；轮次完成后汇总 |
| VAE | 起初单GPU训练统一student；其余卡可采集或审计，采集期间冻结本轮student权重 |
| VAE OU | 12GPU并行motion/phase buckets，每进程独立shard路径/seed |
| diffusion正式 | **4GPU DDP，每卡local batch128→global512**；先完成一个模型，余卡可采集/评估/扩库 |
| multi-seed | 最终重复性评估时可选3组4卡DDP；当前不要求重复训练teacher或diffusion |
| final eval | 卡0主protocol，其他卡按seed/task并行；汇总完整失败分母 |

如果强制用12卡训练同一diffusion，512不能整除12；要显式选择global480/528等并列为工程偏差，或设计真实uneven batching及加权梯度。主线每组4卡保持512最简单。不能“每卡512”后称论文batch512。

根目录[train.sh](../../train.sh)已提供全部注释的本地motion转换、短训、正式训练、恢复、回放与4台服务器独立训练的命令。默认4个动作各1个训练seed，不重复训练。更多motion须先取得参考数据、转换25Hz并审查质量；当前额外8种动作尚未准备。12个Isaac进程的CPU/RAM开销尚未测量，不强求所有卡同时占满。

训练seed与评估seed分开：每motion先用仓库默认训练seed产出teacher，实际值记录于agent.yaml；该checkpoint用不同初始phase/扰动/评估seed做多次rollout，不增加训练次数。只有某motion失败或训练波动明显才追加训练seed。最终论文级重复性实验可另外比较训练seed，不能据单次结果宣称已测量训练方差。

VAE paper只给accum15，未给batch。单卡micro512→effective7680是E；本地micro256→3840也是E。不得与diffusionglobal512混淆。每卡正式teacher env规模先profile512/1024/2048/4096，数据质量和physics吞吐验收后选择。

服务器批量调度使用manifest queue和每GPU独立run目录。已有scheduler则按它执行；没确认不擅自设置后台常驻服务或自动任务。长job设置定期checkpoint、正确SIGTERM处理、恢复命令与log尾部，不把会话中断当全部产物丢失。

## 6. 数据量和时长用测量预算

本次4段CSV共26,066帧，25Hz重采样后约21.7k reference frames。若每frame约100次accepted覆盖，则约2.17M recorded timesteps，再加被拒绝episode及5s尾段物理执行。该量级只是按P4 coverage推算，实际manifest应重算。

每21帧×195维float32的materialized window约16,380bytes；1M窗口约16.4GB，不含raw/metadata/worker复制。本项目lazy windows，只保存raw时序与small index，避免几十GB重复窗口和RAM膨胀。HDF5/分块NPZ需实测dataloader随机读取吞吐；不要一次加载全量并fork复制12份。

训练20M模型参数/gradient/Adam states/EMA通常几百MB，VRAM主要还包括activations、batches和sim。不能只用参数大小估计整个job显存。

**禁止承诺“12卡几小时就完成”。** 首轮记录以下实际数据再算：

```text
teacher_wall_h = 实测每iteration秒 × 目标iterations / 3600
collector_wall_h = 目标实际physics transitions / 实测aggregate transitions_per_s / 3600
updates_per_epoch = ceil(number_train_windows / global_batch)
diffusion_wall_h = epochs × updates_per_epoch × measured_update_seconds / 3600
```

coverage100、epoch1000可能产生数百万optimizer updates；如果预算过高，按pre-registered缩小coverage或更新步预算作阶段性实验，并继续最终数据规模验证。warmup10000 updates若总updates很少，应采用短训profile专用warmup并明确不是正式paper配置。

每模型记录raw samples seen、epochs、optimizer updates、wallclock、GPU hours、best val和last状态。检查epochs不是batch数量、DDP world size改变后global batch没变。

## 7. 吞吐、恢复与迁移

保存每run resolved config、source/asset/data/checkpoint hash、Python锁、GPU型号、precision、TF32、CUDA版本、seed、DDP world_size。resume保存optimizer、scheduler、EMA、global step、各rank RNG/数据sampler状态；DDP checkpoint只由rank0原子写入。

normalizer和P随checkpoint存而非临时文件路径；teacher_map/data_root/artifact_root支持相对位置和root映射。复制数据后校验hash，禁止依赖 `/tmp`、`/dev/shm`、作者用户名或本机绝对路径。

server迁移次序：doctor→G0→固定1个25Hzmotion和teacher短跑→加载本地VAE same-state等价→实际小DAgger shard→diffusion小batch等价→正式规模。先确认serverGPU/headless权限与磁盘后才发长训练。

## 8. 推理与实时预算

25Hz整个控制周期40ms。torch batch1 benchmark必须warmup、CUDA同步、包含guidance梯度、反归一化/state恢复/decoder。报P50/P95/P99和deadline miss率，不能拿batch512吞吐或纯forward时间替代。

第一目标同步物理闭环质量；后续real-time P95<40ms是部署目标，不保证本机或任意PyTorch实现达标。paper约20ms是其TensorRT/异步/硬件环境记录，不可直接移植为本项目承诺。

async推理的deadline不只看推理耗时：计划快照可能已经过时。记录observation_time、planning_time、target_tick、execution_time、age；对超龄结果丢弃或短暂使用此前有效计划，策略要预注册并计入失败/性能。避免用真实reference/teacher作静默fallback。

TensorRT导出是T12优化任务，不能优先取代PyTorch真值和guidance数学验证。当前用户目标是仿真复现，不要求安装ROS2、CppAD或真机网络协议来完成首轮。
