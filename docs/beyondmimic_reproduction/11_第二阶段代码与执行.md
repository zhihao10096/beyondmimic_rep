# 第二阶段代码与执行

实现日期：2026-10-01。代码提供 teacher→D0→CVAE→DAgger→闭环评估→独立 decoder 导出的实际入口。命令清单是仓库根目录的 `stage2.sh`，所有命令保持注释，供你按服务器和显卡安排执行。原来的 teacher 训练命令没有修改。

2026-10-02命令简化：`stage2.sh`只分“现有teacher开始第二阶段”和“扩充teacher”两类。新增`workflow.py`读取[当前teacher登记表](configs/teacher_registry_current.json)，长路径与train/val配对由入口自动填写。当前正式起步库为walk1、walk2、dance1、jumps1、fight1；此前评估记录保持在[原始登记表](configs/teacher_registry_2026-10-02.json)和[13_评估报告](13_Teacher评估结果_2026-10-02.md)。

自动继续DAgger：用户D1模型五项G2均未通过，现提供可执行的`bash dagger.sh`，从D1继续D2、D3……，直到全部motion通过G2 clean，支持断点恢复。实现及运行说明见[14_自动DAgger.md](14_自动DAgger.md)。本次检查26项测试和dry-run，不代表已完成自动物理训练。

## 实现范围

| 文件 | 作用 |
|---|---|
| `source/whole_body_tracking/beyondmimic_stage2/core.py` | 命名观测、67/96/160维契约、CVAE、冻结输入统计、KL、decoder-only API |
| `teacher.py` | 根据原始 agent.yaml 严格加载 RSL actor 和 empirical normalizer，输出 actor mean |
| `data.py` | 独占 run 目录、原子 NPZ shard/manifest、SHA256 审计、直接 memory-map 未压缩 NPZ 训练字段、平衡采样 |
| `isaac.py` | 官方 25Hz G1 环境、观测一致性检查、link-origin raw 速度、物理后且 reset 前的状态捕获、重采样边界、整动作结束控制 |
| `scripts/stage2/rollout.py` | adapter 检查、D0/DAgger 采集、完整 teacher/student 回放 |
| `scripts/stage2/workflow.py` | 登记表驱动的短命令、train/val配对、历轮数据选择、扩库验收入库 |
| `dagger.sh` / `scripts/stage2/auto_dagger.py` | 冻结名单、实际G2控制循环、每轮采集/聚合/训练/评估、断点恢复 |
| `scripts/stage2/train.py` | 单卡纯 PyTorch CVAE 训练、验证选择、精确断点恢复、新 DAgger 轮次 |
| `scripts/stage2/export.py` | 可重新加载验证的 TorchScript decoder，输入只有 latent 和 proprio |
| `tests/test_stage2.py` | 数值、分区、teacher/RSL一致性、DAgger动作选择、梯度累积、恢复与统计冻结测试 |

这些模块单独作为 `beyondmimic_stage2` 包，避免原 `whole_body_tracking` 顶层导入时初始化 Isaac。脚本自带源码路径引导；服务器复制源码后无需为此改 CUDA 或安装新依赖。需要现有 teacher 环境中的 torch、numpy、PyYAML、IsaacLab，以及用于数值验证的 RSL-RL。训练与导出无需启动 Isaac。

## 首次执行与教师选择

2026-10-02当前5项teacher均已通过本轮筛选，使用各自`model_29999.pt`、原`params/agent.yaml`和`params/env.yaml`；不必重复验收即可开始D0。10-01的walk1 model_3000为历史调试权重，未通过G1，不再用于正式命令。

1. 按`stage2.sh`第一类的5条`collect-d0`命令采集，每条自动执行该motion的独立train/val采集。
2. 5项采集完成后执行`train-d0`；再用`evaluate`完整评估所有当前入库motion。
3. 新增teacher使用第二类的`add-teacher`：完整phase0回放和随机phase扰动10秒各20次，两项≥19/20才入库。G1是工程规则，不是论文原始阈值，短程存活不会替代完整G1。
4. 先用 walk1 检查流程，再以所有入库 motion 的 D0 共同训练一个 CVAE。最终多动作模型建议从完整 D0 库重新初始化统计，而不是在单动作统计上悄悄加入新统计。
5. student 评估不合格时收集 DAgger，聚合原 D0 和历轮数据继续训练。teacher 在 student 实际状态上标注，student 执行100%的动作。

不必等12个 teacher 都结束才能评估或采集。空闲卡可以逐个评估已保存的候选 checkpoint，合格后采集不同 motion 的 D0。CVAE 是共同模型，首版单卡训练；当前不提供没有验证的多卡 DDP。服务器可以并行运行不同 motion 的 collector，每个进程必须用不同输出目录，显卡由你分配。

若早期 checkpoint 不过 G1，仍可用 `--allow_unqualified` 跑明确的调试实验；该标志同时写入数据和模型，并要求后续训练/评估显式确认其调试身份。正式命令默认拒绝未合格教师的数据。调试结果不能作为 G2 验收。

## 数学和执行细节

默认 encoder/decoder 都是 `[2048,1024,512]` ELU，latent32；decoder 实际 MLP 输入是 z32+proprio96=128，输出29个 normalized action。encoder 只看 reference67。训练使用 posterior sample，rollout 默认 mean，并保存实际使用的 z；`--latent sample` 可以做单独消融。

损失是 batch/joint 均值 MSE，加 `.01 * batch平均(逐latent求和 KL)`。AdamW、LR5e-4、weight_decay0、累积15个 microbatch、gradient clip1，完整 fp32。累积先按样本数加权，更新前除以实际样本总数，因此尾部不足15个 batch、最后 batch 不满时均正确。logvar 限制[-20,10]用于数值保护，边界写在模型配置中；没有默认 KL warmup。

初始 reference/proprio 统计只从 D0 train 估计，不使用 val/test；以后各轮冻结。标签不另行归一化、不增加 tanh、不裁剪 PD target。teacher 使用 checkpoint 里的 `_mean` 和 `_std`，RSL 2.3 的 epsilon=.01，只应用一次；丢失 normalizer、160维不匹配或带动作 clipping 的 teacher 会直接拒绝。

采集和评估关闭 policy observation corruption，以同一份干净实际状态构建 teacher 标签和 student 输入，这是明确的工程选择。D0/DAgger 保留官方 startup/interval 物理随机化。clean 完整评估保留 startup 材料/默认关节/COM 随机化，关闭 reset pose/velocity/joint noise 与 interval push；`--perturbed` 单独恢复这些扰动。与论文严格比较时需报告这套协议差异。

**PD action offset 与 runtime 默认关节位置分别记录。** `JointPositionAction` 在 startup 随机化前 clone offset，但当前仓库的自定义 `randomize_joint_default_pos` 事件会同步更新它，真实物理检查中二者最大差值为0。proprio/teacher 的 q_rel 按 `data.default_joint_pos` 计算；实际 target 保持官方动作模块行为，另存 `pd_action_offset` 和 `pd_target`，用实际offset验证target公式。没有为了匹配设计公式而改动teacher执行行为。

root proprio 的线速度沿用官方 root COM body velocity，以匹配 teacher；raw root/body 的位置与线速度则统一到 link origin。raw 字段使用 wxyz，anchor Rot6D 为矩阵前两列3×2按行flatten，直接复用官方观测函数并逐项比较 clean teacher160。

## 数据、采样和恢复

每个 collector 运行独占一个新目录。`manifest.json` 列出 schema、motion/checkpoint/agent/env/code/URDF/mesh hashes、joint/body/action/actuator映射、seed、分区、初始phase、采集轮次、物理随机化和 termination 列名。NPZ 每行保存 pre-action raw state、reference/proprio/teacher输入、label、执行动作、实际PD target、episode/env/tick/phase以及terminated/truncated/reset/command_resampled。DAgger 额外保存 mu/logvar/latent_used/vae_action_clean。

终止物理状态在 reward 计算之后、自动reset和command更新之前捕获。非边界步的 `next_*` 保存完整env.step返回时的物理状态，包含interval push；边界步保留reset前的物理状态且 `next_state_valid=false`，防止接到reset后的下一pre-state。`termination_reason` 是 bool向量，列名在 metadata 中；motion_id/teacher_id 是整个 run 的元数据，不重复写字符串数组。完整轨迹标识为 `(run, env_id, episode_id)`。

普通采集保留官方10秒 episode 和 adaptive phase reset。MotionCommand 末尾内部 `_resample_command` 即使没有 done，也增加 generation 并分段。首次 `env.reset` 后主动同步相对参考body目标，不推进phase，避免官方零初始化目标在首次termination检查时造成假失败。完整评估延长 timeout、从phase0开始，在最后一帧执行后标记结束，避免原 command 内部传送制造“成功”。评估保留所有失败trial，输出分母、成功率、Wilson95%区间、每trial长度和终止原因。

训练输入为多个已完成 run 目录，程序拒绝 incomplete manifest、哈希损坏、映射不一致、重复数据，以及同 motion 同 collector seed 在不同轮次跨 train/val/test。训练按 motion/轮次/20个phase区间平衡采样，聚合时D0占25%采样质量，其余分配给历轮DAgger。只保存轻量索引及最多64个shard的训练字段memory-map，不将所有raw轨迹读入RAM；文件映射缓存提高跨motion随机采样效率。

`last.pt` 保存模型、优化器、D0统计来源、完整teacher元数据、数据指纹、模型配置、mapping/contract hash和 Python/NumPy/Torch/CUDA/sampler RNG。原实验恢复要求数据及采样参数相同；追加新数据显式用 `--resume --new_round`，冻结原统计。`best.pt` 根据 held-out action MSE选择，只是候选模型，不能替代物理 G2。

G2 clean 比较要求同motion、相同 teacher checkpoint/原参数、相同评估seed/环境数/协议；每motion student成功率≥90%，较teacher下降≤10百分点，body位置误差≤teacher1.25倍。每个入库motion均应满足，并额外报告扰动结果；最终 test 另用未参与模型选择的评估seed。`--start_phase random`可从随机phase运行到末尾，motion够长时至少保留5秒，输出实际初始phase和独立协议名；随机phase或perturbed成功率不能冒充phase0 clean G1。

## 目前的限制与后续

本机真实验证已完成：11项测试通过；walk1 model_3000完整20次回放17次成功，mean body error约0.0448m，G1尚未通过。真实D0 train256/val128行、完整架构CVAE一次更新、最新student-only DAgger256行、聚合D0/D1再一次更新，以及decoder导出重载均通过。DAgger重算label最大差1.91e-6、decoder动作最大差5.37e-7，234个连续transition的next state与下一pre-state精确一致，跨轮normalizer完全不变。仅更新一次的student完整回放0/2成功；这是一条调试链路，不是收敛模型。

没有默认镜像增强：在验证G1关节轴、左右映射和FK之前，不能任意镜像reference或latent。当前没有接触技能专属评估、视频自动录制、分布式CVAE训练或论文原作者未公开的 stage2 细节。默认 epoch/采样数是可调整工程预算，需要通过多动作闭环结果决定停止。

此代码没有实现第三阶段 diffusion、guidance 或 OU 数据筛选；exported decoder 是第三阶段接口。完整 stage2 复现成立还需要合格的多动作 teacher、正式 D0/DAgger 训练和各motion的 G2结果。测试夹具与真实采集数据严格分开，不能把数值测试通过称为复现成功。

数值测试命令：`python -m unittest discover -s tests -p 'test_stage2.py' -v`。物理 smoke 和当前真实 teacher 验证证据记录在 `references/stage2_implementation_checks.json`。

## 简短入口的默认值与恢复

`workflow.py`只组织调用现有脚本，不更改teacher/CVAE数学、物理接口、奖励或验收阈值。默认读取当前登记表，只选择`admitted_for_initial_d0=true`，核对checkpoint/motion/原YAML/报告哈希；每个采集进程依次运行train和val，多个动作可由用户分配到不同GPU。训练仍为一个统一CVAE的单卡训练。

分服务器采集时，采集机需要对应motion的checkpoint、原params、NPZ和登记表引用的两份验收报告。训练前把所有入库motion的完整train/val目录按`data/stage2/动作名/轮次目录`汇总到训练机，保留manifest和shard原始字节，并复制同一份当前登记表。纯CVAE训练只需这些数据和登记表，不要求再次复制teacher权重或启动Isaac；会核对manifest的teacher/motion/配置身份以及shard完整性。

- `collect-d0 --motion 动作名`：train seed100、val seed200；32环境；train2500步、val1000步。`collect-dagger --round N`改用100+N、200+N；可用`--num_envs`、`--steps`、`--val_steps`调整采集预算。
- `train-d0`自动选所有入库动作D0；`train-dagger --round N`要求每项D0和第N轮train/val齐全，保留存在的历史DAgger轮次。扩库新motion不伪造之前不存在的旧轮次。任何已有目录残缺都会报错，不悄悄跳过。
- `train-d0/train-dagger`默认沿用训练脚本50 epochs、100000 samples/epoch、batch512，可传`--epochs`、`--samples_per_epoch`、`--batch_size`、`--output`。参数是工程预算，应以闭环G2和扰动结果决定迭代次数。
- 精确恢复D0：`python scripts/stage2/workflow.py train-d0 --resume logs/stage2/cvae_d0/last.pt`。精确恢复D1：`python scripts/stage2/workflow.py train-dagger --round 1 --resume logs/stage2/cvae_d1/last.pt`。保持登记表、数据和原训练预算/seed一致；恢复时epochs为总上限。`--student`用于新DAgger轮，`--resume`用于原轮恢复，二者不能混用。
- `evaluate`默认seed300、20环境，与本次G1配对；结果保存到自动命名的新`artifacts/stage2/student_evaluation/`目录，并打印每个motion及汇总G2。`--perturbed`为seed400完整动作扰动补充，独立报告。最终heldout/random-phase评估仍可用底层`rollout.py`入口，按原协议生成相同seed的teacher baseline。
- `add-teacher`在`logs/rsl_rl/g1_flat`中按原env.yaml查motion，使用该训练目录最大iteration的checkpoint；同motion存在多个候选训练目录时拒绝自动选择。可用`--teacher_root`指定只包含所选训练目录的父目录。失败保留旧名单；合格报告及batch summary保存在`artifacts/stage2/teacher_candidates/`，移动服务器时须连同登记表引用的报告复制。
- 默认`--data_root data/stage2`；替换同motion的权重/参考后，会拒绝旧teacher标签身份不一致的数据。需要新目录重新采集，并对训练命令使用相同`--data_root`。原日期登记表不自动修改，扩库仅更新当前登记表；同时验收不同motion时，入库写入会加锁并合并最新名单。
- 任一workflow命令添加`--dry_run`仅打印底层命令；不生成假数据、不启动Isaac/训练、不改名单。dry_run允许尚未产生的student/D0路径用于检查计划；正式执行仍严格检查文件和完成状态。

本次短入口只做命令展开和CPU守卫验证，未启动新的正式D0/CVAE/DAgger训练。已有物理评估仍见13报告，不能把命令简化当作新G2结果。
